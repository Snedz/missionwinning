## 2026-08-08 — The Athlete Card did not pay its costs (`.612`)

**`.610` added a card to `/profile` and broke three `@gate` specs, all three by re-introducing rules this repo had already written down.** Nothing caught it for two ships, because the gate aborts at step 16 on a bundle red that predates this branch, and steps 17–18 — hero e2e and a11y — are therefore unreachable through `npm run gate`. They only ran here because they were run out-of-band, against a production build with the gate's own `BUILD_ENV`. A gate that stops early is a gate whose last steps have no owner.

**Tap targets.** The frame, backdrop and badge chips shipped as `size="sm"` — `h-9`, 36px — and the share button as the default `h-10`, 40px, against the 44px floor `thumbSweep.ts` enforces. `/profile` already had two chip rows that pass (`ProfilePreferencesCard`, `ProfilePrivacyCard`), and both use `className="min-h-[44px] tap-target"`; the new file used the `size` prop instead and landed 8px short. Worth noting `ProfilePrivacyCard`'s own chips are `min-h-[40px]` and pass only because they render behind `hasKey && !dnt` and so are absent from the swept zero state — a precedent that looks safe and is not.

**The one-red-action rule, reintroduced in a new file.** The share button took the default variant, which is `bg-primary-fill` — the screen's one do-this-now colour — putting a second red on a route whose one red is "Send magic link". This is exactly the defect class `.241` fixed repo-wide when `selected ? 'default' : 'outline'` was painting *selections* red at ~20 sites, and `/profile` was one of the two routes it named. A rule enforced only by an e2e lane that the gate cannot reach will be broken again by the next new file; it was.

**Dead weight on the route that could least afford it — and the estimate that was wrong.** `.610` put the frame and backdrop catalog in `shareCard.ts` as `if (backdrop === 'grid') …` chains. That file is imported by `WorkoutVictorySheet`, which renders on `/active`, so webpack compiled the whole catalog into `/active`'s entry — for cosmetics a victory card, which passes none, can never reach. The painters now live in `src/lib/share/cardCosmetics.ts` and are handed to the renderer as closures on `ShareCardData.cosmetics`; the dependency runs one way. The ids ride along beside the closures so the clamp assertions in `athleteCardData.test.ts` keep reading what they always read.

**What the move was actually worth, since the first number here was a guess dressed as a measurement.** `/active` gzipped: **443.5** (`.608`) → **444.6** (`.611`) → **444.3** (`.612`). The catalog is verifiably gone — `rule-field`/`poster-block` now appear only in `.next/static/chunks/app/(app)/profile/page-*.js`, and `/active`'s page chunk went 36.8 → 36.6 KB — but it was worth **0.3 KB**, not the 1.1 KB I attributed to it from the 5.9 KB of source. gzip deduplicates `ctx.strokeRect`/`ctx.fillRect` runs against the renderer already sitting in that chunk, so raw source size predicts almost nothing about the delta. **The other ~0.8 KB of `.610`–`.611` growth on `/active` is not the catalog and is not attributed here** — mw-core's `athleteCard.ts` was checked and is absent from the route. Recording the residual rather than rounding it away: the change is still right (dead code on a route is dead code, and the seam belongs where it now is), it is just a tenth of the win the source diff implied.

**The guard for that invariant could not see the defect it was written for.** It matched `from ['"]…cardCosmetics['"]`, so the mutant that adds a bare `import './cardCosmetics'` — a side-effect import, which pulls the module in exactly as hard — **survived**. Fixed to match all four spellings the toolchain admits (`from`, side-effect `import`, dynamic `import(…)`, `require(…)`), each falsified separately. This is `CLAUDE.md` §6's *"a guard keyed to one spelling of a defect has only ever tested that spelling"*, caught the only way it gets caught: by mutating and watching it stay green.

**One hero spec was still red here, and this entry blamed the wrong thing — see `.613`.** `workout complete updates Mission Score on Today` failed twice at exactly 23.1s. Because it had passed on `master` and at `.608` and the only thing that had changed was this branch, the entry recorded it as "open and mine". It was neither: `.613` reproduced it on demand by pinning the clock to 19:30 and made it pass at 09:30, on this same build. The test had a wall-clock dependency and it was a Saturday evening. Hero went 68/71 → 70/71 here on the two `/profile` repairs above; the third was never this branch's.
