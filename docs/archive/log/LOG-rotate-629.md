## 2026-08-08 — The page that was named after a person and held none of one (`.614`)

**S2 of [IDENTITY_SOCIAL_PLAN.md](docs/IDENTITY_SOCIAL_PLAN.md).** `/profile` was a 413-line settings screen wearing the nav label "You": email, units, goals, push cadence, billing, backup, import, legal. The single block on it that belonged to an athlete was the badge shelf. Settings moved to **`/account`**; `/profile` became the **Athlete Page** — Identity (call sign + when you started) · The line (what you have done) · the shelf that already shipped. Local only: no server call, no public projection, no share beyond the existing card, all of which are S4 and gated on CLUB_PLAN C2.

**The call sign had a home nobody could find.** `operatorName` has existed since the leaderboard shipped — 24 chars, one writer in `leaderboard/computeLocalStats.ts` — but the only editor was a field on `/leaderboard`, a *parkable* surface. Identity was editable exclusively from the one screen that ranks people, which is backwards for a product whose social thesis is profile-not-feed. The new editor shares the same storage, so the two cannot drift.

**The line exists because of the D8 void rule.** An identity page whose only content is badges is blank for exactly the athlete who has trained twice and earned none. [`careerLine.ts`](src/lib/careerLine.ts) derives sessions, volume moved, distinct exercises, best week and days trained from `workoutHistory` alone — no new storage, nothing to keep in step. Tombstones are excluded, because `benchmarks.ts` and `dayReview.ts` skip them and a total that counts a deleted session resurrects it in a number. Dates go through `localDateKeyFromIso`, never `toISOString().slice(0,10)`. Before the first session the card says what it will hold rather than showing nothing. **`/profile` is pinned at 0 red actions** — a record is not a task, and the call-sign Save is outline on purpose; `/account` keeps the magic-link red at 1.

**Re-exporting the locales for one new namespace uncovered a shipped i18n hole 26 keys wide.** `rewards/catalog.ts` emits `titleKey: 'rewardBadgeFirstBlood'` and `titleKey: 'rewardRank1'` from its data tables. **No catalogue defined any of them.** They were present in the shipped English pack only because the committed `public/locales/en/today.json` was *stale* — so every badge and every rank rendered the call-site English fallback in all fifteen languages, and had since the rewards surface shipped in `.505`–`.543`. This is `.252`'s `coachWhySteadyWeek` exactly: *a key the app renders, present in the pack, defined in no source module.* Both existing i18n gates are blind to it by construction — `i18n:parity` compares packs to packs, so a key missing from **all** of them is perfectly consistent, and `i18n:coverage` greps `.tsx` for literal `t('…')` calls, which never sees a key emitted from a data table. New [`rewardsKeyParity.test.ts`](src/lib/rewards/rewardsKeyParity.test.ts) **derives** the required set from `BADGE_DEFS` and `RANKS`, so a fourteenth badge cannot ship stringless, and asserts pack-equals-catalog-default so the fallback stops being a lie. `deployReadiness`'s namespace counter was right the whole time and could not have caught this: it proves a pack *ships*, never that it is *complete*.

**A second collision, same cause.** `learnExpandedBanner` and `learnExpandedDesc` were claimed by **both** `guidebookLocales` and `learnLocales` with different text, and guidebook merges last — so the Learn page has been rendering *"Now with even more content!"* while `LearnPage.tsx`'s own `defaultValue` says *"Beyond the Basics"*. `learnLocales` is the typed owner and matches the call site; the guidebook copies are removed. `localeFootprint.test.ts` had been green only because the stale export hid the disagreement.

**And the export had never been run for five namespaces at all.** Adding `athlete` regenerated `public/locales/` for the first time since `.252` made re-exporting safe, and **75 files appeared** that had never existed: `firstSteps`, `zeroState`, `notification`, `whatsNew` and `rewards` — every one a shipped surface. 385 files changed, 90 new. That is the full extent of the drift `.252` diagnosed and could only fix going forward: the exporter and the splitter disagreed by construction, nobody could safely re-export in between, and `en/today.json` stayed frozen around a namespace layout that had moved underneath it. The runtime path is the TS catalogues via `hydrateResources`, so the missing packs bit the HTTP-override path and the translator handoff rather than the shipped app — but they are also precisely what made the 26 undefined keys invisible.

**Also shipped:** `athleteLocales` (34th namespace, en/es/fr/pt), and [`athleteLocales.test.ts`](src/i18n/athleteLocales.test.ts), which reads the `defaultValue` out of the four component sources rather than listing keys — so a new string on either surface is in scope the moment it is written.
