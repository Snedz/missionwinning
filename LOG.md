Chronological record of shipped work. Newest first.

**Rotation rule:** keep **≤15 entries** here, and never let the file grow. When over, move the oldest entries (whole `##` sections, order preserved) to `docs/archive/log/` and list the file in [docs/archive/INDEX.md](docs/archive/INDEX.md). Enforced by `src/lib/logBudget.test.ts` — until `.242` it was enforced by nothing, and the file had reached **27 entries / 127KB**.

> **The `≤20KB` half of this rule was unmeetable and is retired.** An entry here averages ~5.6KB, because the house style is to explain the defect class rather than name the change — which is the most valuable thing in this repo and not something to trade away for a byte count. Fifteen entries is ~84KB; obeying 20KB would have meant keeping **three**. So the count rule stands, and the size rule becomes a **ratchet**: the file may shrink, never grow. If the founder wants a hard byte ceiling instead, that is a call about house style, not about this file.

## 2026-08-09 — Eight design directions, built so they can be compared (`.643`)

The founder asked for three design options. `.641` shipped one and treated the other two as later stages — a misread of the instruction, not a disagreement about it. This builds the set: **eight art directions for the marketing surface**, on a board, at `docs/design/variants/`.

**The property that makes it a comparison and not a gallery is copy identity.** All eight render the same DOM from the same module, and the generator extracts the visible text of every variant and **refuses to write if any of them differs**. Without that assertion the board silently degrades into a comparison of two different pages, and the difference is invisible at thumbnail size — which is the size at which the decision actually gets made. That single check is why this is a generator and not eight hand-authored files.

It forced a real change: `stats`, `anywhere`, `freeCore`, `navLinks` and the page metadata lived **inside `index.astro`**. Fine with one rendering, wrong with nine. They now live in `sites/www/src/lib/homeContent.ts` and the real page reads it too, so the board and the site cannot drift.

**Why `docs/design/variants/` and not `sites/www`.** Seven of the eight are *illegal* on the app surface by construction — `off-palette-colour` is repo-wide and unscoped, and `gradient` / `emoji-as-icon` / `centred-section-root` are scoped to `sites/www`. Exploring alternatives there would have meant allowlisting the core palette rule, which is how a ban list dies. `docs/` is outside every guard's roots, verified against all twelve, and confirmed empirically: the design-system scan went 935 → 937 files, and both new files are the two `sites/www` sources this ship added. **The variants are invisible to it.** A winner gets ported back in, where all the rules apply again, and each page prints what that would cost.

**The eight.** A1 modernist poster (the shipped system, re-rendered for a like-for-like comparison) · B1 sport editorial, B2 Archivo-new-ground and B3 free identity (the three leashes: reds pinned, reds and type pinned, nothing pinned) · C1 mission dossier, C2 instrument, C3 cinematic, C4 zine.

**Two constraints shaped the work and are worth recording, because both look like laziness from the outside.**

*Type.* This environment cannot fetch a font — egress is blocked to every font host, as to every image host. The one break: the Archivo embedded in `www-spec-sheet.html` carries **wght + wdth** (`font-stretch 62–125%`), unlike the repo's weight-only subset, so condensed and expanded cuts exist for free. Every variant therefore uses Archivo for display. Substituting `system-ui` for a display face would have been worse than reusing one: it renders as Liberation Sans on the machine that screenshots these, making the board a comparison of font fallbacks.

*Photography.* Three frames exist in the entire repo. For a comparison board that is a **feature** — the same three under eight grades isolates art direction and nothing else. Duotones and the halftone are baked with PIL because CSS cannot express them; everything else is a `filter`.

**Four things only rendering caught.** The first pass mapped duotone highlights to the *full* brand red, full amber and full sand, and every one came back as a flat wall of colour with the photograph gone and white type unreadable on it — a duotone whose light end is a saturated hue has no highlights left to read a picture by. The ink belongs in the midtone; the page's accent supplies saturation. The halftone at a 3px cell on an autocontrasted source was noise, not a photograph. B2 was indistinguishable from A1 until the warm shift was tripled. And C1 read as "green B2" above the fold because every marker that makes it a dossier — ruled stock, stamps, section numbers — was below it.

Also: the 1-bit halftone is a **PNG**, not WebP. As WebP the three frames were 589 KB against 124 KB for the untreated base, because every dot edge is high-frequency detail a lossy codec must keep. PNG run-length codes a bilevel image: 35 KB. And the treated frames themselves are **not committed** — they are a deterministic intermediate from three committed photographs and a committed script, so they build into a gitignored `.cache/` rather than sitting in a folder whose stated rule is rendered output only.
